# 鱼来 0.1.0

中文与 ASCII 字符组成的浏览器多人鱼来世界。每台电脑运行便携启动器，浏览器通过 WebRTC 组成网络。游戏状态、身份和记忆使用浏览器 IndexedDB 保存；启动器只提供网页文件与临时配对通道。

## 开始玩

1. 解压整个「鱼来-0.1.0.zip」，保留 `www` 文件夹与程序在一起。
2. Windows 10/11 双击「鱼来.exe」。游戏打开固定本地地址 `http://127.0.0.1:39241`。
3. 第一次设置昵称。公开展示打码昵称；每个浏览器配置文件拥有独立身份。
4. 点击「连接同事」，复制自己的发布地址给同事。同事访问该内网地址后下载自己的启动包、解压并运行，包中带有你的接入地址，自动尝试配对。
5. 已有启动器的同事可直接输入你的发布地址连接。后续会尝试已缓存的入口。

访问地址需要当前网段能够访问 TCP 39241，并能建立浏览器 WebRTC 直连。当前没有 TURN 中继。启动器不自动修改防火墙或浏览器设置。

关闭游戏网页即退出玩家网络，启动器仍可发布代码；托盘右键「退出启动器」停止发布服务。其他已接入浏览器可以继续维持世界。账号、余额和历史不要依赖浏览器默认缓存，请使用「导出身份与记忆」备份；备份含身份密钥，保管在自己的设备上。

## 操作

- 拖动水域探索，滚轮缩放。「到水面」「去海底」快速定位。
- `F` 创建鱼，`S` 创建景物，`E` 从水面投食，`M` 到海底，`P` 打开「我的鱼」。
- 左侧「◎ 我的鱼」列出本人创建的存活鱼，显示完整昵称、性别、缩略图、今日运动量、近 24 小时进食量和饥饿状态。点击鱼卡定位并跟随观察；本人鱼的观察面板也显示完整昵称，可展开最近 7 日的运动记录。
- 点击「水面投食」或按 `E`，独立设置鱼食字符和颜色，查看预览后到水面选位置。支持一个中文、中文标点或 ASCII 字符，每颗消耗 1 字符；取消设置或投放不扣额度。
- 画板支持自由手绘转换和逐格编辑中文、ASCII、颜色。右键擦字；提交前可以撤销草稿。
- 创建鱼使用 15×15 画板、2–15 字；造景使用 20×20、至少 2 字。必须八方向整体连通。
- 造鱼时可选择公／母，默认公；蓝色 ♂ 表示公，粉色 ♀ 表示母。性别随投放、存档、备份与联机保存，旧版鱼显示「性别未记录」。
- 选择世界位置确认投放后消费字符，任何条件不返还。创建或摆景不能覆盖鱼或已有地形。
- 鱼投放后不能人工修改、移动或删除。点鱼只能观察。鱼自主左右转头、移动、争食与进食。
- 场景默认共享编辑：可搬动、90°旋转、二倍放大或二分之一缩小、移除。放大复制产生的新字符要支付配额，缩小和删除不返还。
- 世界右上角显示玩家、鱼、景物及字符余额；右下角为当前网络的公共聊天室。
- 聊天随世界存档持久保存，重开及联机合流会按消息 ID 补齐、去重。「查看更早的聊天」可逐批查看旧消息，保存时不裁掉早期记录。导出身份与记忆也包含当前世界及聊天。
- 点击海底记忆碑查看已保存的世界合影。

## 生态规则

海底边界的每一格和水下造景的每个字符，每小时各有 1% 概率在八方向相邻的空格发芽，排除鱼、鱼食、已有海草、地形和纪念碑。海草使用深浅随机的绿色「草」，每株顶端每小时同样有 1% 概率向上长一格。按整点逐小时结算，创建不足一小时的造景或草尖不参与该次抽签；生长时钟随存档和联机保存，重复快照不会重新抽签。自然生长不花字符额度。

超过两字的海草根部固定，草茎随机摆动，逐格检查摆动路径，不能穿过造景，也避开鱼、食物和其他海草。鱼按原有浅水 10 格、深水 5 格的眼睛视野寻找海草，八方向接触后沿用大鱼优先的争食规则，吃下的绿色「草」成为鱼体、计入进食记录并解除饥饿。仍扎根的海草不会五分钟后沉积；根部或中段被吃断、支撑造景被移走时，断开的部分脱落为鱼食。

眼睛只认 `0 O o 。 . 口`。每个眼睛独立提供视野：浅水 10 格、深水 5 格。盲鱼不主动追食，碰到仍能吃。八方向接触，鱼食原位长成身体字符；同一结算步同时接触时，字数多的鱼胜出，并列采用稳定伪随机选择。

水平速度为 `2 × 外接宽 / 字数` 格/秒，垂直速度为 `2 × 外接高 / 字数`。鱼、转头及新长出的字符均受地形阻挡。玩家可以围困鱼；不会产生额外碰撞伤害。

连续 24 小时不吃食，随机丢掉一个外轮廓字符。断裂只留最大连通块为鱼，其他每字变成鱼食；最大块只有一字时不再保留鱼。

鱼况中“今日运动”按北京时间自然日累计实际游动距离，单位为格；水平／垂直移动一格计 1，同一结算步同时横、竖各移动一格计 √2，原地转头、碰壁和相机移动不计。每日记录随世界存档、联机快照与备份保存，同一鱼同一天的重复副本取较大累计值合并，不重复叠加。分区期间采用累计值收敛，不能视为强一致的逐帧轨迹。旧版没有运动记录的鱼从更新后开始累计，面板注明开始时间。

“近 24 小时进食”按实际吃下的鱼食颗数统计，从字符的生态历史去重计算，字符后来脱落或烧毁仍保留进食记录。连续 24 小时未进食即显示“饥饿”，进食后解除；尚未吃过食的鱼从投放时开始计算。饥饿退化不会解除饥饿，退化倒计时和饥饿状态分别显示。

玩家鱼食必须点击亮蓝色水面行投放，慢慢下沉。造景挡住后停在上方；生成 5 分钟后就地变成沉积，附着支撑物、随支撑物搬动。同位置多颗食物依次堆积，不覆盖已有字符。没有支撑时到期会先失去可食性，继续下沉至支撑处固化，这是首版对未定边界的实现选择。

每个新世界初始 20 字，累计在线每小时 +1；后台正常运行计在线，长时间休眠不计。未满一小时的累计时间保存在身份内跨世界保留。合并世界，同一身份的初始 20 只认一次；保留全部作品并可能产生负余额，由后续在线奖励抵扣。

## 实现与验证范围

第一版面向 Windows；浏览器使用原生 Canvas、Web Crypto、IndexedDB、EventSource、WebRTC 和压缩流。启动器使用 Windows 内置 .NET Framework，无需安装 Node.js 或 Python。

在线网络采用最多 8 个直接邻居、消息去重和转发；普通鱼游动由当前选出的临时浏览器协调，每秒发布位置和变化字符，30 秒补发完整快照，离开后其他浏览器接替。协调者是普通玩家浏览器，没有常驻游戏后端。合流时保持鱼不变，把与鱼或其他景物重叠的造景整体移至最近空位；极端满世界时会提示仍待安置。

身份签名保护人工操作，鱼编辑和退款指令被拒绝。当前对故意篡改自然模拟状态的恶意节点不提供强安全保证，配额也无法阻止用户新建浏览器身份。网络分区时状态会暂时分歧，恢复后按字符历史与稳定规则合并；这需要继续做复杂长时分区测试。

无人在线后 240 小时内湮灭，按连续小时计算，包含周末和节假日。浏览器保存世界检查点及最近在线时间；不足 240 小时重开会恢复原世界、作品和账本，不重发初始配额。达到 240 小时后再次打开或从长时间休眠恢复，会将旧世界合影记为湮灭并创建新世界，余额重新从 20 开始。全员离线期间没有运行中的浏览器，过期判定在下次进入时执行；仅启动器运行不延长期限。旧版检查点按保存时间迁移。

全员离线没有可靠中央登记，判定依据是本地最近在线记录，异常退出可能使用最后一次成功保存的时间。发现旧根仍有在线玩家时会恢复、合流并修正纪念记录；未发现活跃旧根时不会自动复活过期作品。历史包含图片、简要记录和聊天原文，所有副本丢失后不能恢复。

本轮世界湮灭时，聊天正文按可见字符拆开，随机分布在下一轮海底，成为固定、不可编辑／搬动／删除的地形，不消耗玩家配额。空白不占格，中文、ASCII、组合文字和完整表情都会保留；昵称和时间不参与沉积。相同消息使用相同字符身份和稳定随机规则，多个浏览器分别开启下一轮再合流不会复制沉积；发现旧世界仍存活时会撤销错误沉积。空间不足的文字保留来源并等待空位，不直接丢弃。新一轮聊天室从空记录开始，更早的聊天可在对应纪念卡展开查看；每轮只把本轮聊天传到下一轮海底。

本轮 46 项规则测试通过。Edge 专项测试通过，覆盖鱼况统计、本人鱼筛选、定位跟随、小屏观察、自定义鱼食、240 小时期限、持久聊天与聊天沉积。真实 WebRTC 测试验证了运动记录同步、实际协调者退出后的统计保留，并使用 207 条聊天形成 1,078 个沉积字符，验证重开、合流去重和误判纠正；浏览器没有报错。期限和鱼况时间边界采用模拟时间验证。当前 Windows 应用程序控制策略阻止运行新编译启动器，浏览器测试使用 Node 静态网页／信令服务。Chrome 当前未安装，Firefox 测试发行版在图形初始化时未能启动。本轮与初版的验证范围见「验证记录.md」。

500 人是目标：初版基线的 500 参与者、10,000 字符、40 步 Node 模拟中，每步耗时中位数约 61 毫秒、p95 约 132 毫秒；六邻居模型能到达全部 500 节点。这些基线没有包含本轮鱼况界面、完整签名和真实浏览器传输，不等于 500 台办公电脑真实内网验收；正式推广前需在实际网段测试握手、流量、浏览器资源占用和长时间运行。详细记录见项目根目录「验证记录.md」，原始结果保存在 `test-output`。

## 开发

源文件 `www/engine.js` 是生态、账本与世界合流，`fish-status.js` 管理鱼况统计口径和记录合并，`chat.js` 管理聊天记录和海底沉积字符，`lifecycle.js` 管理 240 小时离线期限与存档恢复，`network.js` 是配对及 WebRTC 传输，`app.js` 管理浏览器副本和界面，`launcher/Program.cs` 是静态发布与临时信令。

在 Windows PowerShell 运行 `./build.ps1` 构建 `dist/鱼来/鱼来.exe` 和干净发行 ZIP。编译器为 Windows 自带的 .NET Framework C# 编译器。

如果已有 `dist/潮生` 兼容目录，构建会同时更新其中的 `www`、使用说明与验证记录，保留原启动器。已打开的旧页面需要刷新才能载入更新；固定本地地址和 IndexedDB 数据库保持不变。`node tests/served-ui.cjs` 可检查当前 `http://127.0.0.1:39241` 实际发布的“我的鱼”入口、快捷键绑定及鱼况模块，其他测试地址可通过 `TIDE_UI_URL` 指定。

安装 Node.js 后，`npm test` 运行规则测试，`node tests/benchmark.mjs` 检查模拟负载。浏览器测试需 Playwright：`node tests/browser-smoke.cjs`，也可用 `TIDE_TEST_MODULES` 指向已有 Playwright 包。测试启动器只监听本机 39081–39084，浏览器使用临时配置。缺少 Chrome 时联机测试使用另一独立 Edge 实例；`TIDE_SKIP_FIREFOX=1` 可跳过 Firefox。`node tests/browser-lifecycle.cjs` 使用本机随机端口的 Node 测试服务和 Edge 临时配置，专项验证离线期限，不运行 Windows 启动器。

完整产品规格见「鱼来世界开发规格.md」。暂定水深、浅深分界、速度系数与结算步长集中于 `www/engine.js` 的 `CONFIG`，可根据真实试玩调整。

`node tests/browser-chat.cjs` 使用 Node 本机信令服务与独立 Edge 配置，验证真实 WebRTC 聊天及沉积合流。联机节点应更新到本轮发行代码；旧版没有持久保存的聊天无法补回。聊天及沉积来源仍受现有传输大小和世界空间上限约束，浏览器数据与所有备份全部丢失后无法恢复。
