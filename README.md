# 鱼来

中文与 ASCII 字符组成的浏览器多人鱼来世界。联机模式仅限同局域网内游玩，玩家在 Windows 或 Linux 的 x64 电脑上运行便携启动器，玩家浏览器间通过 WebRTC 组成网络。浏览器保存游戏状态、身份和记忆。启动器提供网页文件、临时配对和热更新。

## 开始玩

1. 下载并完整解压 Release 页面对应系统的最新压缩包（Windows 为 `fishcome-VERSION-windows.zip`，Linux x64 为 `fishcome-VERSION-linux-amd64.zip`），或同系统玩家发给你的便携启动压缩包（包内带邀请码，启动后自动尝试配对）。
2. Windows 10/11 双击「鱼来.exe」，Linux x64 运行「./fishcome」（依赖系统默认浏览器）。游戏自动打开固定的本地网页地址 `http://127.0.0.1:39241`；升级或换包后用同一浏览器访问该地址即可保留原有身份与存档。
3. 浏览器第一次接入设置昵称。聊天、作品和鱼谱会公开展示你的完整昵称；每个浏览器配置文件拥有独立身份。
4. 也可分享给其他同事联机玩：点击「连接同事」，复制自己的「邀请码」给同事。同系统首次使用的同事可以直接使用你从本机下载的便携启动包（包内带有邀请码，解压运行后自动尝试配对）；不同系统的同事请先下载适合自己系统的发布包，再粘贴邀请码连接。
5. 已有启动器的同事可直接粘贴邀请码连接。后续会尝试已缓存的邀请码；旧版地址缓存和下载包会自动迁移为邀请码。

每邀请一位新用户完成昵称注册并首次通过邀请码接入世界，发码账号获得 **10 鱼元** 推广奖励，新用户保留原有初始 20 鱼元。同一新账号只奖励一次；无邀请码注册、已有账号重连、自邀、失败连接及后台自动补邻居均不发奖。奖励写入带新用户签名的世界账本，刷新、备份恢复和世界合流不会重复累加，并可用于创建、投食或抵扣负余额；世界湮灭后仍按原规则重置为 20。

新邀请码包含发码账号，游戏中的「我的邀请码」和下载包按当前账号生成。同一启动器的多个浏览器身份可分别推广，下载链接保留对应账号；欢迎页与托盘没有指定账号时，使用该启动器当前按节点标识排序的首个在线账号。旧版仅含地址的邀请码仍能接入，推广奖励归首次实际接入的对端账号。新账号注册信息保存在浏览器身份中，更新前的已有账号不补发奖励。联机双方需更新网页与启动器以解析带账号的邀请码。与现有配额机制一样，去中心化身份无法阻止用户清空数据或新建浏览器身份重复注册。

邀请码采用 `YL1` 版本的路由编码与校验，由本机生成和解析，不需要中心服务器或邀请码数据库。连接窗口、托盘复制、欢迎页、邻居入口和新下载包不展示明文地址。完整邀请码可以还原路由，因此这项功能隐藏界面和分享文本中的明文地址，不能提供 IP 匿名或地址加密；实际 P2P 直连设备仍能获取对端 IP。请完整复制邀请码，损坏或截断的代码会被拒绝。

访问地址需要当前网段能够访问 TCP 39241，并能建立浏览器 WebRTC 直连。当前没有 TURN 中继。启动器不自动修改防火墙或浏览器设置。

关闭游戏网页即退出玩家网络，启动器仍可发布代码；可通过系统托盘菜单「退出启动器」停止发布服务（Linux 托盘依赖系统桌面支持通知区域，托盘复制邀请码需要系统已安装 `wl-copy`、`xclip` 或 `xsel`，否则可在游戏「连接同事」中复制）。其他已接入浏览器可以继续维持世界。账号、余额和历史不要依赖浏览器默认缓存，请使用「导出身份与记忆」备份；备份含身份密钥，保管在自己的设备上。

## 操作

### 偶尔看看，鱼自己生活

每条鱼自动拥有一种小性格：独处、凑热闹、海底闲逛或探索造景。性格不需要选择，只影响闲游；看到食物仍优先觅食，饥饿时沿用普通寻食规则。鱼卡与观察面板用一句话展示习惯。

附近且没有造景隔挡的鱼，实际累计相处 45 秒会认识为熟鱼。熟鱼偶尔短暂同游，实际分开三分钟后再遇见会留下重逢故事；附近三至五条鱼每分钟最多同游 18 秒。它们仍遵守逐格碰撞、转头和繁殖规则，不需要提高好感或执行互动任务。

鱼在人工造景附近实际停留 45 秒后，可能把那里当作常去之处，闲游时短暂停留、再靠近；爱探索的鱼会尝试绕着造景游。大家仍可照常搬动或移除造景。

海里每三分钟进入一个天气时段，可能出现最多 55 秒的轻水流、光带或浮游食物，也可能风平浪静。水流与光带轻微影响闲游方向，不增加游速或穿透碰撞。浮游食物为免费的淡绿色 `*`，每次最多 10 颗；未被吃掉的在出生 75 秒后消散。吃到后成为鱼体，之后沿用普通增长、繁殖、饥饿、脱落和沉积规则。

创建、第一次吃食／吃草、认识熟鱼、重逢、常去造景、小鱼出生和鱼生结束会留下最近的鱼生片段。回来时自然展示其中一条，也可从「我的鱼」的「最近的鱼生」查看、定位。没有未读数量、领取步骤或定时上线要求；全员离线不补模拟故事。最近片段随存档、备份与联机保存，世界最多保留 512 条，展开显示与本人鱼有关的最近 40 条。联机双方都需要更新并刷新页面。

- 拖动水域探索，滚轮缩放。「到水面」「去海底」快速定位。
- 点击左下角「3D」开启或关闭立体海景。默认使用平面海景，浏览器记住你的选择。立体海景中的鱼使用半透明果冻拼豆，带透光、高光和轻微弹性起伏；同一条鱼的颗粒共用节奏，游动时身体出现连续波浪摆动，后半段动作稍明显，换向带短暂弹性缓冲，停止后逐渐收敛为呼吸起伏。文字随身体平移但不拉伸旋转，相邻颗粒的柔和连接跟随摆动。动作只改变显示，不改变实际鱼元位置。系统选择减少动态效果时静止显示。造景保留圆形拼豆颗粒、字符留白、轻微厚度和柔光；鱼眼保留发光提示，投放预览也使用相同颗粒。保留原来的字元、颜色、点击位置和玩法，支持 CPU 软件绘制。
- `F` 创建鱼，`S` 创建景物，`E` 从水面投食，`O` 到水面，`M` 到海底，`L` 连接同事，`H` 查看玩法，`P` 打开「我的鱼」。快捷键仅在没有打开弹窗、且未编辑文字时生效，触发按键不会写入新打开的编辑框。
- 左侧「◎ 我的鱼」列出本人创建的存活鱼，显示完整昵称、性别、缩略图、今日运动量、近 24 小时进食量和饥饿状态。点击鱼卡定位并观察，默认不跟随；可手动开启「跟随观察」。本人鱼的观察面板也显示完整昵称，可展开最近 7 日的运动记录。
- 点击「水面投食」或按 `E`，独立设置鱼食鱼元和颜色，查看预览后到水面选位置。支持一个中文、中文标点或 ASCII 字符，每颗消耗 1 鱼元；取消设置或投放不扣额度。
- 造鱼和造景使用拼豆画板：输入一个或多个字符并点击「添到盘里」，每个字符生成一颗独立的豆子，相同字符也独立。点击盘里的豆子夹取，它立即从盘里消失；笔上只持有一颗，点击空格放下后笔就空了，拖动不会重复铺字。夹取另一颗会把原先夹着的豆子放回，也可点击「放回盘里」取消；擦除、替换和清空会把取下的豆子归还。支持逐颗配色、上色笔、框选批量上色、撤销重做，盘、笔和画板的豆子状态一起恢复。字符盘、输入框和颜色固定在画板上方，常用字符与说明按需展开；中文输入法、键盘单格编辑和辅助手绘转换继续可用。每格一个字符，投放时每格消耗 1 鱼元，准备和配色不扣额度。造鱼的 2–15 字、造景至少 2 字、八方向连通、余额、合法字元与颜色、鱼名检查不变；鱼眼提供 0、O、o、。、.、口 六种快捷字符，无眼仍可投放，造景不显示鱼眼提示。
- 造鱼时可以输入鱼名，长度按 Unicode 鱼元数计算，不能超过投放时的鱼身鱼元数。默认名为「账号名的第 N 条鱼」，N 为新增后当前拥有的存活鱼数量；默认名超长会截短，自定义名字超长则不能投放。名字随创建记录保存，鱼长大或缩小时不改名。
- 「我的鱼」的「鱼谱」页签以家谱展示血缘，选择任意本人鱼可查看相关祖先、兄弟姐妹、配偶与后代，包括其他作者的亲鱼和已消失的鱼。父母在上、子女在下，已消失的鱼用虚线框标识；点击存活节点定位观察。点击海中任意鱼的详情卡片上的「查看鱼谱」也可直接查看它的血缘。家谱支持滚轮缩放、拖动平移和缩放按钮，可上下左右滚动，多代记录随存档、备份与联机保留。旧鱼和自然出生的小鱼使用适合出生字数的默认显示名。
- 创建鱼使用 15×15 画板、2–15 字；造景使用 20×20、至少 2 字。必须八方向整体连通。
- 造鱼时可选择公／母，默认公；蓝色 ♂ 表示公，粉色 ♀ 表示母。性别随投放、存档、备份与联机保存，旧版鱼显示「性别未记录」。
- 选择世界位置确认投放后消费鱼元，任何条件不返还。创建或摆景不能覆盖鱼或已有地形。
- 鱼投放后不能人工修改、移动或删除。点鱼只能观察。鱼自主左右转头、移动、争食与进食。
- 场景默认共享编辑：可搬动、90°旋转、二倍放大或二分之一缩小、移除。放大复制产生的新鱼元要支付配额，缩小和删除不返还。
- 世界右上角显示玩家、鱼、造景及鱼元余额；造景数仅为仍存在的人工造景数量加记忆口数量，当前世界固定有一个记忆口，自然沉积和旧聊天地形不计入。右下角为当前网络的公共聊天室。
- 聊天随世界存档持久保存，重开及联机合流会按消息 ID 补齐、去重。「查看更早的聊天」可逐批查看旧消息，保存时不裁掉早期记录。导出身份与记忆也包含当前世界及聊天。
- 点击海底记忆碑查看已保存的世界合影。

## 海里的六个小秘密

- 气泡偶尔显示「咕」「噜」，极少数显示「？」。文字由气泡出生标识决定，刷新和联机不会重新抽签，上浮与扩张规则照旧。
- 熟鱼实际分开后重逢，约三分之一的重逢会轮流冒出「好」「久」「不」「见」，共六秒；最近的鱼生也会留下它们用暗号打招呼的片段。
- 点击旧聊天沉积的单个字，可以在观察面板展开对应聊天全文，查看原作者和时间。
- 同一个鱼元保持原字连续经过至少三次自然出生，观察面板与所选鱼的鱼谱会显示「祖传一个字」和可追溯的祖辈。改眼、脱落后重新吃入和仅仅同字不算连续继承；缺少完整鱼元路径的旧记录不推测继承。
- 鱼游过海底聊天沉积，附近两格内恰好有相同的鱼身文字时，旧字会轻轻发光。
- 鱼实际在造景附近相处45秒后记住一处位置。造景搬离七格范围或移除后，它偶尔尝试回去；实际离开再返回会留下「风景换了」，再遇到原造景则留下「原来你搬到这里了」。移除造景不会抹掉这处记忆，全员离线不补故事。

彩蛋不发放鱼元或增加碰撞实体。旧地记忆与片段沿用存档、备份和联机；此次鱼生联机规则更新，伙伴需全部更新网页并刷新后连接。

## 偶尔路过的随机事件

整片海每六分钟有一次45%的事件抽签，事件最多持续一分钟，留出至少五分钟安静时间；条件不合适时也会风平浪静。画面左上角会自然出现「看看」入口，可以定位事件。全员离线不补演，开场后才恢复模拟也不会重抽；联机共享已选定的位置、参与鱼和稀有变体。

- **深海巨影**：淡淡的字符鲸影缓缓游过，稀有时会跟着一条小鲸影。
- **海洋打了个嗝**：一小片海草连续冒出气泡，最后浮出一个「嗝」。
- **漂流瓶路过**：文字瓶随水流经过，可在水中点击读信；偶尔信里只有「？」，署名为「全文完」。
- **鱼群临时开会**：三至四条彼此附近的熟鱼短暂停留，轮流冒出「嗯」「？」，最后散会。
- **海底开花**：生长至少一小时的海草短暂开出「花」，再散为淡淡光点。
- **流星掉进海里**：字符微光从水面斜斜落下，拖着一小段星光。
- **海洋电台**：断续的文字播报逐段显示，可点入口慢慢读；偶尔主播会去吃草。
- **倒着游的游行**：附近熟鱼尝试一起游、一起转头，留下「刚才的方向不算」。

视觉效果不占用鱼元，不成为食物或碰撞实体。会议和游行只影响短暂闲游，饥饿、觅食、繁殖及逐格碰撞优先；附近参与的鱼会留下鱼生片段。事件计划最多保留32份，随存档、备份及联机保存。此轮鱼生联机规则为3，联机伙伴需全部更新网页并刷新。

## 生态规则

### 三种稀有异象

整片海每10分钟有一次独立抽签：克苏鲁0.2%、哥斯拉0.2%、幽灵船1%，其余时段不出现；事件结束后至少间隔两小时。左上角有观察入口。异象角色用指定鱼元重复排出形体，与普通鱼、造景及余额分开记录。详细规则见 `稀有异象设计.md`。

- 克苏鲁与哥斯拉从地下100层升到当地海床上方，出土预告20秒，均在10分钟后消失。克苏鲁只用「克／苏／鲁」，有八条独立挥动的触须，每条最多捕获一条鱼；被捕的鱼停止游动、进食和配对，仍按原时钟饥饿，在该次异象结束时永久消失。一次最多捕获八条，已有鱼自然死亡也不补抓，鱼谱与历史保留。
- 哥斯拉只用「哥／斯／拉」，背脊预热8秒后用「原／子／吐／息」组成吐息，每分钟最多一次。吐息逐格展开、由造景与海床遮挡，直接接触的鱼身鱼元永久消失；剩余身体只保留最大八方向连通块，至少两字就存活，未烧毁的脱离碎片变成普通鱼食。真正受伤后存活会记录「哥斯拉原子吐息幸存者」，没有眼睛仍可作为盲鱼存活。
- 幽灵船只用「幽／灵／船」，在海面漂浮一小时。整船每分钟以1%概率脱落一个船体字，变为免费的「蛆」鱼食，下沉、进食、增长、饥饿和沉积沿用普通规则；实际吃到的鱼记录「吞下过幽灵船上生长的船蛆」。船消失后，已经掉落或吃进鱼身的蛆继续存在。

捕获、永久烧毁、船体缺口与船蛆出处随备份及联机保存；刷新和旧快照不复活已经消失的鱼元。全员离线不补演捕获、吐息与船蛆；已发生的捕获在到期后重开或从休眠恢复时先完成消失结算。异象期间不新增普通随机事件。此次鱼生联机规则为4、异象规则为1，伙伴需全部更新网页并刷新。

每条鱼成功吃下一个鱼元后，至少间隔 **60 分钟** 才能再次进食；按连续时间计算，跨整点不会重置。同一结算步也只能吃一颗，普通鱼食、海草和浮游食物共用这个限制。新投放和自然出生的鱼可立即吃第一餐；繁殖双亲分别计时，继续共用视野。吃饱期间不会主动追食或参与争食，仍正常闲游；观察面板显示下次可进食的等待时间。刷新、存档恢复和联机接替保留计时，旧存档从已有真实进食记录恢复。

新世界创建时，海底每列独立以 1% 概率长出一个绿色「草」，同时在空水域随机加入 2–10 条名为「默默无名的鱼」的鱼，随机鱼体、颜色和性别。初始鱼通过普通投放逻辑生成，遵循同样的鱼名长度、鱼体连通、眼睛视野、游速、碰撞、进食、饥饿脱字、繁殖、后代归属和鱼谱规则。它们归属海洋内置账号，不占用玩家的初始 20 字，也不出现在玩家的「我的鱼」中；每条内置账号按正常额度支付鱼体成本。出生凭据按世界起源固定并随联机和备份保存，刷新不会再次投放。已有世界不补种；世界湮灭后开启的新世界会重新生成。相关生成与凭据校验在 `www/genesis.js`。

海宽固定为 1000 格，左右循环相通；鱼的身体、转头碰撞、寻食、繁殖以及镜头都按环形空间处理。海底在世界生成时构造 80–100 格深度的随机周期折线，并随存档、备份和联机快照保存，刷新不会重新生成。海底本身是固定地形，不消耗鱼元，也不能编辑。鱼食在对应列的实际海底停止／沉积，海草从实际海底边界发芽，纪念碑位于海底上方。

独立世界合流时，按起源时间、起源标识的稳定顺序保留其中一份已有海底，不重新抽签。旧存档按其起源生成固定海底，原本落在新海底下的鱼、景物和食物会安置到水域内，保留作品与账本；旧海草失去支撑时转为鱼食。联机玩家需要更新到本轮网页代码并全部刷新，混用旧平面世界规则的浏览器会提示重新刷新后连接。

所有新昵称都完整展示，不再打码。旧记录中已被打码保存的文字不能凭空还原；对应作者重新上线后，使用已知完整昵称更新聊天、作品及鱼谱展示，原有签名记录保持原文。

公母鱼在八方向相邻、且接触没有隔着造景的情况下，连续贴合 5 秒后结伴繁殖 1 小时。接触中断或长时间休眠会重置尚未完成的 5 秒计时；旧版没有性别记录的鱼不参与配对。繁殖期间两鱼固定相对位置，一起移动和水平翻转；合体外接宽、高和总鱼元数决定游速，沿用普通鱼算法。两条鱼的眼睛共同寻食，食物或海草长在实际吃到的亲鱼身上，双方的进食、饥饿和运动记录分别统计。期间不与第三条鱼配对。

一小时结束时，将进入繁殖时记录的双方接触鱼元从父母身上转移为独立小鱼，不复制鱼元、不扣额度；期间因公母鱼饥饿而碰巧脱落的鱼元不会被小鱼继承。小鱼须至少两个、整体相连、来自父母贴合的鱼元，否则取消本次出生并解除绑定。任何一方消失也会取消繁殖。仍处于宽限期的世界恢复后，繁殖时钟保留，已到期的繁殖在恢复模拟时结算。

小鱼至少有一个眼睛；若没有，就随机将一个继承鱼元换成六种眼睛之一，保留原颜色与父母来源。小鱼公母各有一半概率。归属先比较来自父鱼／母鱼的鱼元数，多的一方获得小鱼；相同时比较分裂后父母剩余鱼元数，再相同则随机归属一方。随机结果随出生记录保存、联机时不会重复抽签。自然出生的小鱼显示在归属者的「我的鱼」中，可查看性别、出生时间、父母来源；亲鱼显示繁殖倒计时和合体游速。

海底边界的每一格和水下造景的每个鱼元，每小时各有 1% 概率在八方向相邻的空格发芽，排除鱼、鱼食、已有海草、地形和纪念碑。海草使用深浅随机的绿色「草」，每株顶端每小时同样有 1% 概率向上长一格。按整点逐小时结算，创建不足一小时的造景或草尖不参与该次抽签；生长时钟随存档和联机保存，重复快照不会重新抽签。自然生长不花鱼元额度。

超过两字的海草根部固定，草茎随机摆动，逐格检查摆动路径，不能穿过造景，也避开鱼、食物和其他海草。鱼按原有浅水 20 格、深水 10 格的眼睛视野寻找海草，八方向接触后沿用大鱼优先的争食规则，吃下的绿色「草」成为鱼体、计入进食记录并解除饥饿。仍扎根的海草不会五分钟后沉积；根部或中段被吃断、支撑造景被移走时，断开的部分脱落为鱼食。

眼睛只认 `0 O o 。 . 口`。每个眼睛独立提供视野：浅水 20 格、深水 10 格。盲鱼不主动追食，碰到仍能吃。八方向接触，鱼食原位长成身体鱼元；同一结算步同时接触时，字数多的鱼胜出，并列采用稳定伪随机选择。

海草的每个鱼元每分钟独立以 `(100 - 所处水深)%` 的概率产生气泡，例如水深 80 格为 20%。新海草满一分钟后参与抽签。气泡为白色「泡」，初始 1×1，以每秒 1 格逐步上浮，每累计上浮 25 格变为 2×2、3×3、4×4……的「泡」方阵；任意一个鱼元触及水面时整个气泡消失。气泡没有碰撞体积，可穿透鱼、海草和造景，不可被鱼吃，也不消费鱼元。它产生后不随海草摆动或消失而被牵动，直到触海面。

气泡的分钟抽签、出生位置和时间随世界保存并联机去重，刷新或导入备份不会把气泡变回初始大小；已经浮出水面的气泡不会被旧快照复活。长期离线恢复不补出已经消失的历史气泡。相关速度与扩张参数在 `www/bubbles.js`。

水平速度为 `2 × 外接宽 / 字数` 格/秒，垂直速度为 `2 × 外接高 / 字数`。每个鱼身鱼元占一格碰撞体积，鱼与鱼不能重叠或穿过；空白格不占碰撞体积。游动逐轴检查占格，转头检查扫过的全部格子，进食也不能长入其他鱼。繁殖合体用双亲全部实际鱼元作为一个碰撞体，可彼此接触，但会被第三条鱼阻挡。碰撞只阻止相应移动，不额外扣字或造成伤害；受阻不计入运动量。鱼、转头及新长出的鱼元也受地形阻挡，玩家可以围困鱼。

造鱼投放不能覆盖已有鱼，重叠位置以红色预览并拒绝投放，不消费配额。旧存档或世界合流产生的鱼体重叠，由协调浏览器把重叠鱼整体放到最近空位，保留鱼身、归属、血缘和账本，修正位置不计入运动量；繁殖中的双亲一起平移，保持相对位置。如果世界没有空位，会提示并等待空位后重试。被拒绝的投放会清理重试记录，防止协调者接替后再次生成。

连续 24 小时不吃食，随机丢掉一个外轮廓鱼元。断裂只留最大连通块为鱼，其他每字变成鱼食；最大块只有一字时不再保留鱼。

鱼况中“今日运动”按北京时间自然日累计实际游动距离，单位为格；水平／垂直移动一格计 1，同一结算步同时横、竖各移动一格计 √2，原地转头、碰壁和相机移动不计。每日记录随世界存档、联机快照与备份保存，同一鱼同一天的重复副本取较大累计值合并，不重复叠加。分区期间采用累计值收敛，不能视为强一致的逐帧轨迹。旧版没有运动记录的鱼从更新后开始累计，面板注明开始时间。

“近 24 小时进食”按实际吃下的鱼食颗数统计，从鱼元的生态历史去重计算，鱼元后来脱落或烧毁仍保留进食记录。连续 24 小时未进食即显示“饥饿”，进食后解除；尚未吃过食的鱼从投放时开始计算。饥饿退化不会解除饥饿，退化倒计时和饥饿状态分别显示。

玩家鱼食必须点击亮蓝色水面行投放，慢慢下沉。造景挡住后停在上方；生成 5 分钟后就地变成沉积，附着支撑物、随支撑物搬动。同位置多颗食物依次堆积，不覆盖已有鱼元。没有支撑时到期会先失去可食性，继续下沉至支撑处固化，这是首版对未定边界的实现选择。

每个新世界初始 20 字，累计在线每小时 +1；后台正常运行计在线，长时间休眠不计。未满一小时的累计时间保存在身份内跨世界保留。合并世界，同一身份的初始 20 只认一次；保留全部作品并可能产生负余额，由后续在线奖励抵扣。

## 实现与验证范围

当前支持 Windows 10/11 与 Linux x64 便携运行；浏览器使用原生 Canvas、Web Crypto、IndexedDB、EventSource、WebRTC 和压缩流。启动器使用 Go 编译为独立原生程序，解压即可运行，无需安装 Node.js 或 Python；Linux 托盘依赖系统桌面支持通知区域，托盘复制邀请码需要 `wl-copy`、`xclip` 或 `xsel`。

在线网络采用最多 8 个直接邻居、消息去重和转发；普通鱼游动由当前选出的临时浏览器协调，每秒发布位置和变化鱼元，30 秒补发完整快照，离开后其他浏览器接替。协调者是普通玩家浏览器，没有常驻游戏后端。合流时保留鱼身鱼元，先整体分开重叠鱼，再把与鱼或其他景物重叠的造景整体移至最近空位；极端满世界时会提示仍待安置。

身份签名保护人工操作，鱼编辑和退款指令被拒绝。当前对故意篡改自然模拟状态的恶意节点不提供强安全保证，配额也无法阻止用户新建浏览器身份。网络分区时状态会暂时分歧，恢复后按鱼元历史与稳定规则合并；这需要继续做复杂长时分区测试。

无人在线后 240 小时内湮灭，按连续小时计算，包含周末和节假日。浏览器保存世界检查点及最近在线时间；不足 240 小时重开会恢复原世界、作品和账本，不重发初始配额。达到 240 小时后再次打开或从长时间休眠恢复，会将旧世界合影记为湮灭并创建新世界，余额重新从 20 开始。全员离线期间没有运行中的浏览器，过期判定在下次进入时执行；仅启动器运行不延长期限。旧版检查点按保存时间迁移。

全员离线没有可靠中央登记，判定依据是本地最近在线记录，异常退出可能使用最后一次成功保存的时间。发现旧根仍有在线玩家时会恢复、合流并修正纪念记录；未发现活跃旧根时不会自动复活过期作品。历史包含图片、简要记录和聊天原文，所有副本丢失后不能恢复。

本轮世界湮灭时，聊天正文按可见鱼元拆开，随机分布在下一轮海底，成为固定、不可编辑／搬动／删除的地形，不消耗玩家配额。空白不占格，中文、ASCII、组合文字和完整表情都会保留；昵称和时间不参与沉积。相同消息使用相同鱼元身份和稳定随机规则，多个浏览器分别开启下一轮再合流不会复制沉积；发现旧世界仍存活时会撤销错误沉积。空间不足的文字保留来源并等待空位，不直接丢弃。新一轮聊天室从空记录开始，更早的聊天可在对应纪念卡展开查看；每轮只把本轮聊天传到下一轮海底。

历次玩法专项验证见《验证记录》。[打开验证记录](验证记录.md)

500 人是目标：初版基线的 500 参与者、10,000 鱼元、40 步 Node 模拟中，每步耗时中位数约 61 毫秒、p95 约 132 毫秒；六邻居模型能到达全部 500 节点。这些基线没有包含本轮鱼况界面、完整签名和真实浏览器传输，不等于 500 台办公电脑真实内网验收；正式推广前需在实际网段测试握手、流量、浏览器资源占用和长时间运行。详细记录见项目根目录「验证记录.md」，原始结果保存在 `test-output`。

## 开发

源文件 `www/engine.js` 是生态、账本与世界合流，`fish-status.js` 管理鱼况统计口径和记录合并，`chat.js` 管理聊天记录和海底沉积鱼元，`lifecycle.js` 管理 240 小时离线期限与存档恢复，`network.js` 是配对及 WebRTC 传输，`app.js` 管理浏览器副本和界面，`launcher/`（Go）负责静态发布、临时信令、便携包导出、热更新与桌面托盘。

构建需要 Go 1.25 或更高版本。运行 `./build.ps1` 默认按当前系统构建（Windows 在 PowerShell 下生成 `dist/鱼来/鱼来.exe` 与 `fishcome-VERSION-windows.zip`，Linux 使用 `pwsh` 生成 `dist/鱼来/fishcome` 与 `fishcome-VERSION-linux-amd64.zip`），也可通过 `-TargetOS windows` 或 `-TargetOS linux` 指定目标系统。

合并请求由 `Check` 工作流验证。正式发包由 `Release` 工作流处理。两者共用 Windows 和 Linux 的发行包验收步骤。将工作流和构建脚本提交、推送到 master 后，在要发布的提交上创建并推送版本标签，例如：

```powershell
git tag v0.1.1
git push origin v0.1.1
```

两条工作流都在 Windows 和 Linux 上运行规则测试与 `go test ./...`、编译启动器，再解压 ZIP 实际启动程序、校验所有网页资源，并用 Chromium 检查首次注册、弹窗、造鱼、下载名称、刷新恢复、双启动器联机与热更新流程。正式发行在验收全部通过后才上传发行包。用户按系统下载 Release 附件（Windows 为 `fishcome-VERSION-windows.zip`，完整解压后双击根目录「鱼来.exe」；Linux x64 为 `fishcome-VERSION-linux-amd64.zip`，完整解压后运行根目录「./fishcome」）；包内只包含程序和必需的 `www`，不含源码、测试或验证文档。用户手册可在 Release 说明中打开。ZIP 使用英文名称避免 GitHub 删除中文文件名前缀；发布说明与下载链接直接使用实际附件名称。更新时可通过游戏内热更新升级，或先退出旧启动器再运行新包，浏览器仍从原本的固定本地地址 `http://127.0.0.1:39241` 恢复身份和存档。

也可在 GitHub 的 Actions → Release → Run workflow 中选择分支（通常为 master），填写版本标签直接发布，例如 `v0.1.1`。标签不存在时，工作流构建本次所选分支的提交，测试与打包通过后才自动创建标签和 Release，不用事先手工打标签。标签已存在时，工作流构建其对应的原提交；重复执行更新同名 ZIP 附件，不移动原标签。大小写 `v`／`V` 都支持，推荐使用小写。

带后缀的版本（如 `v0.2.0-beta.1`）会发布为预发行版。发布使用 GitHub 自动提供的令牌，无需另配个人令牌。日常推送 master 不自动发布。修复工作流后请从 Run workflow 创建一次新运行；旧运行的 Re-run jobs 仍会使用旧版工作流。

本地浏览器发布验证需先运行 `npm ci` 和 `npx playwright install chromium`；测试使用 Playwright 自带的 Chromium。CI 会固定当前工作流的构建、验证工具，再切换发行标签代码；旧标签的旧验证脚本不会绕过新版检查。

本地可用 `./build.ps1 -Version 0.1.1 -OutputDirectory ./dist/release`（默认当前系统，可用 `-TargetOS windows` 或 `-TargetOS linux` 指定）构建，再用 `./scripts/test-release.ps1 -ArchivePath ./dist/fishcome-0.1.1-windows.zip` 或 `./scripts/test-release.ps1 -ArchivePath ./dist/fishcome-0.1.1-linux-amd64.zip` 在对应系统检查解压后的发行包（Windows 可用 PowerShell，Linux 使用 `pwsh`）。每次打包从独立的新目录收集文件，已有输出目录中的旧文件不会混进 ZIP。

Windows 默认构建时，如果已有 `dist/潮生` 兼容目录，构建会同时更新其中的 `www`、使用说明与验证记录，同步更新对应启动器以支持邀请码。已打开的旧页面需要刷新才能载入更新；固定本地地址和 IndexedDB 数据库保持不变。`node tests/served-ui.cjs` 可检查当前 `http://127.0.0.1:39241` 实际发布的“我的鱼”入口、快捷键绑定及鱼况模块，其他测试地址可通过 `TIDE_UI_URL` 指定。

安装 Node.js 后，`npm test` 运行规则测试，`node tests/benchmark.mjs` 检查模拟负载。浏览器测试需 Playwright：`node tests/browser-smoke.cjs`，也可用 `TIDE_TEST_MODULES` 指向已有 Playwright 包。测试启动器只监听本机 39081–39084，浏览器使用临时配置。联机测试使用两个独立的 Playwright Chromium 实例。`TIDE_SKIP_FIREFOX=1` 可跳过 Firefox。`node tests/browser-lifecycle.cjs` 使用本机随机端口的 Node 测试服务和 Edge 临时配置，专项验证离线期限，不运行启动器。

完整产品规格见「鱼来世界开发规格.md」。海宽、固定海底生成与环形坐标在 `www/geography.js`；浅深分界、速度系数与结算步长集中于 `www/engine.js` 的 `CONFIG`。

生态自动调节由 `www/ecology.js` 实现：附近31×31格实际水域占用达到20%时，繁殖接触时间由5秒延长到20秒；达到40%暂停新配对。海草寿命72–120小时，生长概率随密度由每小时1%降到0.5%、0。自然沉积满48小时后每小时以2%概率风化，拥挤处为5%；人工作品、主动改字的沉积、纪念碑和聊天记忆受保护。迁移旧存档的老海草有24–48小时过渡期。

`www/archive.js` 每天压缩超过7天的已结束记录；日常JSON达到8 MB时，改为整理超过24小时的已结束记录。活实体依赖、家谱凭据及最近80条聊天保留。归档正文存于IndexedDB，联机按需补齐，接收时检查内容哈希、原签名和来源，备份包含全部归档。旧聊天与「过去的作品与收支」按需查看，不增加日常操作。归档减少常规快照负担，完整历史仍会占用本地存储；大量人工作品也仍可能填满世界。

专项验证：`node tests/browser-ecology.cjs`、`node tests/browser-archive.cjs`；`node tests/ecology-pressure.mjs` 是30天逐小时资源压力模拟，不代表真实多人长期联机验收。

`node tests/browser-chat.cjs` 使用 Node 本机信令服务与独立 Edge 配置，验证真实 WebRTC 聊天及沉积合流。联机节点应更新到本轮发行代码；旧版没有持久保存的聊天无法补回。聊天及沉积来源仍受现有传输大小和世界空间上限约束，浏览器数据与所有备份全部丢失后无法恢复。
